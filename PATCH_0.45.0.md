# NEON LIFE 0.45.0 — Simulation Pipeline Recovery

## Что сломано в 0.44.0

На границе суток Kernel открывал и сверял тысячи бизнес-счетов по одному. Каждый шаг выполнял повторный поиск и полное копирование массива счетов. Один большой временной шаг ещё завершался, но серия мелких шагов зависала при переходе через полночь.

Ежедневная экономика дополнительно создавала отдельные `consumer-pool:*` и `workforce-pool:*` счета для районов и каждого бизнеса. Касса бизнеса дважды теряла себестоимость проданного товара, склад не получал физическую проводку, проценты по долгу исчезали без контрагента, а компании ежедневно получали неподтверждённые 8% прибыли дочерних бизнесов.

## Что изменено

- сверка Kernel переведена на индекс счетов и пакетное применение транзакций;
- старые синтетические consumer/workforce счета автоматически объединяются в канонические системные счета;
- добавлен единый `labor-market` для агрегированной выплаты зарплат;
- fallback-платежи образования направляются в существующий `city-services`, а не создают псевдосчета учреждений;
- себестоимость остаётся бухгалтерским расходом, но больше не списывается из кассы второй раз при продаже;
- денежная касса рассчитывается в той же целочисленной точности, что и Kernel-проводки;
- продажи товара создают физическую `inventory-transfer` проводку;
- проценты по долгу перечисляются на `credit-bureau`;
- удалено ежедневное создание денег в казне компаний через неподтверждённые 8% прибыли;
- усилен world-integrity тест: он обязан пересечь полночь, сравнить крупный и дробный шаг, проверить отсутствие утечки счетов и ограничить число компенсационных проводок;
- runner integrity-теста использует локальный TypeScript без `npx` и завершает зависший прогон через 60 секунд с ошибкой.

## Результат

В диагностическом городе переход через полночь сократился с зависания дольше нескольких минут до примерно 1.3–1.4 секунды. Рост счетов на суточном тике сократился примерно с 1400–1500 до одного канонического системного счёта. Число ежедневных domain-reconciliation проводок в контрольном прогоне снизилось с 2243 до 20.

## Совместимость

Формат сохранений не менялся. При первом следующем тике старые `consumer-pool:*` и `workforce-pool:*` счета будут компактно объединены в системные счета без потери балансов.
